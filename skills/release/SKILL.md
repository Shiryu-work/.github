# リリース手順

状態の意味は `リリース/方針.md`、検証の意味は `開発/検証.md` を管理元とします。このSkillはGitHub操作順だけを持ちます。

## 手順

1. 対象リポジトリ、作業ブランチ、作業中PR、基底・先端SHA、レビュー状態、マージ可能状態、`release` ラベル、現在先端のワークフロー実行を確認する。
2. 既存の作業中PRを使い、対象PRが `main` 向けであることを確認して `release` ラベルを付ける。
3. 現在先端の `.github/workflows/release.yml` 実行を確認し、`リリース/方針.md` の状態として判定する。
4. 検査失敗を修正する場合は `release` ラベルを外し、同じPRへ修正を積む。修正後にラベルを再付与して最新先端を再検証する。
5. 成功後、現在の基底SHA・先端SHAが検証時点と同じか確認する。変わっていれば再検証する。
6. 利用者の依頼範囲が `main` マージまで含む場合は、必要ならレビュー可能状態へ変更し、状態と先端を再取得してsquash mergeする。
7. `main` 後にプロダクト固有のデプロイ・公開結果を取得できる場合は確認する。
8. 中止して通常開発へ戻る場合は `release` ラベルを外す。

報告は `リリース/方針.md` の状態を使います。
