# 構成規約

リポジトリ内部の物理構造と責務配置を管理します。

## 責務をルートで表す

リポジトリが自由に決められるルートは、保存形式ではなく責務を表します。`docs/`、`文書/`、`data/` のような汎用収納ルートを共通の既定値にしません。

標準構造は次です。

```text
/
├─ AGENTS.md
├─ README.md
├─ 検証.sh
├─ プロダクト/
├─ 開発/
├─ ウェブ/
├─ 文章/
├─ 根拠/
├─ リリース/
├─ 収録/
├─ 設計/
└─ skills/
```

プロダクト固有のドメイン成果物、実行時処理、素材、設定等は、実際の責務または外部ツール契約からルートを追加します。

## `処理/` を汎用実行物ルートにしない

`scripts/` を日本語化しただけの `処理/` を共通の収納ルートにしません。「何かを処理する」は実装形式であり、利用側から見た責務ではありません。

実行可能なartifactも、実物のownershipとconsumer lifecycleで分類します。例えば次の責務は互いに別です。

- product runtime / projection実装 — `実装/` 等
- deterministic validator — `検証/` 等
- artifact / projection builder — `生成/` 等
- 実物からread-onlyな派生状態を作る処理 — `状態確認/` 等
- local toolchain、仮想環境、command起動adapter — `開発環境/` 等

これらの名前を全Productへ固定配布することが目的ではありません。実際の責務を確認し、generic `処理/` に異なるlifecycleを混在させないことが目的です。

実装moduleに密着したunit / release testは、同じownershipと変更lifecycleを持つならco-locationして構いません。すべてのtestを形式だけで `検証/` へ移しません。

## 生成物とgeneratorは利用責務で命名する

生成方式ではなく、生成物を誰が何のために使うかで名前を決めます。

`catalog` は、利用者・API・MCP等が項目を列挙・探索・取得する実際のcatalog artifactに使います。generatorがcatalog以外に個別item、handoff、index、bundle、公開payload等も生成する場合、generator全体まで `catalog` と呼ぶ必要はありません。`配布`、`projection` 等、実際のconsumer責務に合う名前を選びます。

source manifestとgenerated artifactを同じ管理元として扱いません。manifestは「何を含めるか」、generatorは「どう導出するか」、generated artifactはconsumerへ渡すprojectionです。

生成物内のID、public URL、external Tool名等は、Repository内部generatorのphysical nameとは別contractとして判断します。公開生成物へ露出することだけを理由にstable扱いしません。

## 同じ責務は一つの管理元へ置く

同じ現在値、関係、対象集合を複数のファイル・ディレクトリへ手入力しません。別表現が必要なら参照または生成で扱います。

## 日本語と外部識別子を分ける

リポジトリ内部で自由に決める論理名・物理名は日本語を使用します。

公開URL、外部API、永続ID、公開スキーマ、プロトコル、言語・フレームワーク・ツールが固定する名前は外部契約として別に扱います。

## 安定識別子を存在だけで固定しない

識別子がファイルや設定に存在すること、生成物や公開面へ露出することだけでは、永続互換を要求する安定識別子とは判断しません。

次のような実際の互換境界が成立している場合は、物理pathとは分けて安定識別子として保護します。

- 独立したconsumerや第三者が参照している
- 外部API・protocol・schema・toolが綴りを固定している
- 永続保存済みdataや外部成果物がその識別子を参照している
- 変更側だけでは同時更新できないconsumerとのcontractになっている

一方、Draft中の識別子、停止中のconsumer、同一ownerがproducerとconsumerを同じ変更で更新できる識別子は、存在していることだけを互換維持の理由にしません。公開用の生成物へ出力される場合も、それだけでexternal contract成立とはみなしません。

stable identityか、内部locatorか、external contractかは別に判断します。既に成立した外部contractは守り、まだ固定されていない暫定識別子は不要に早期固定しません。

## ファイルは責務と利用経路で分ける

一つのファイルに独立した責務や異なる利用経路を抱え込ませません。分割判断はサイズではなく責務と利用経路で行います。

常に一緒に読まれ、一つの責務として自然な内容まで細片化しません。現在の責務も利用経路もない独立ファイルは残しません。

## AGENTS.mdは階層ルーターにする

リポジトリ直下の `AGENTS.md` は常時必要な最小ルールと責務別入口だけを持ちます。責務ディレクトリに `AGENTS.md` を置く場合、その下位領域固有の参照先だけを追加します。
