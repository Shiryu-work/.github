# UX監査

完成したウェブを `ウェブ設計原則.md` とプロダクト固有の目的・要求に照らし、利用者が目的を達成できるかで監査します。視覚デザイン、HTML意味構造、文章、外部事実の正しさはそれぞれ別責務です。

## 1. 全体導線

- 誰が何を達成する導線か説明できるか
- 利用者の目的から入口が作られているか
- 再訪者が主要作業へ短く戻れるか
- 重要な入口が装飾・説明・二次機能へ埋もれていないか
- 不要な画面遷移・確認・入力・往復がないか
- 中断、戻る、再開が必要な作業で逃げ道を消していないか

## 2. 画面

- 開いた時点で画面の役割が分かるか
- 主要情報・主要操作・副次操作の区別がつくか
- 現在状態、処理中、完了、失敗を見分けられるか
- 実際に発生する空状態・エラー・利用不可等が未設計でないか
- 判断に必要な条件が操作時点にあるか
- モバイル / デスクトップで重要情報や読み順を失わないか

## 3. 操作

- 操作結果の反応が分かるか
- 破壊的・不可逆な操作が通常操作と紛れないか
- 内部IDや前画面の記憶を利用者へ要求していないか
- エラーから次に何をすればよいか分かるか
- キーボード、フォーカス、タップ、ブラウザ標準操作を理由なく壊していないか

## アクセシビリティとの境界

キーボード操作、フォーカス、拡大、再配置、色以外の情報伝達等、利用可能性と直接重なる項目はUXでも確認します。WCAGの適合水準をプロダクト要求にする場合は `../プロダクト/要求.md` へ明示します。

参考: https://www.w3.org/TR/WCAG22/

## 点数へ潰さない

ヒューリスティックの達成率をUX品質点数にしません。一つの重大な導線問題は、多数の軽微項目を満たしていても問題です。重要な作業で実利用者が完了できるか不明なら、必要に応じて作業ベースの利用性確認を行います。

## 指摘

```text
監査レベル: 全体導線 / 画面 / 操作
利用者の目的:
観測した問題:
利用者への影響:
上位原則または要求:
修正案:
確認方法:
```
