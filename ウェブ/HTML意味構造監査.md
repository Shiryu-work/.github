# HTML意味構造監査

Webの内容と操作がCSS上の見た目だけでなく、HTML要素の意味としても表現されているかを監査します。文章、UX、視覚デザインとは別責務です。

## 文書アウトライン

- ページの主題と主見出しが対応しているか
- 見出し階層が内容の親子関係を表しているか
- 見た目のためだけに `h1`〜`h6` を選んでいないか
- 見た目は見出しなのに汎用要素だけで表現していないか

## ランドマーク / ページ領域

- 主要内容を `main` として識別できるか
- ナビゲーションを `nav` として識別できるか
- `header` / `footer` / `aside` を実際の用途に合って使っているか
- ランドマークを細かく増やしすぎていないか

## セクショニング

`article`、`section` 等を構成要素都合やCSS用の囲いとして使わず、実際の内容に合って選びます。意味を持たないまとまりは汎用要素で構いません。

## 内容の意味構造

- 一覧、手順、表、引用、コード、時刻、画像等を内容に合う要素で表現できているか
- 配置目的だけに表等を使っていないか
- 装飾画像へ不要な意味を与えていないか

## 操作要素・フォーム

- ナビゲーションはリンク、現在画面上の操作はボタンという基本用途と一致するか
- クリック可能な `div` / `span` で標準操作部品を再実装していないか
- 入力欄とラベル、説明、エラー、まとまりの関係がHTML上で表現されているか
- 無効 / 選択済み / 展開済み等の状態が見た目だけに閉じていないか

## DOM順序

DOM順序、キーボードのフォーカス順序、視覚順序が不自然に食い違っていないか確認します。CSSによる大きな並べ替えやデスクトップ / モバイル別DOMの二重管理を安易に使いません。

## ARIA

標準HTMLで表現できる意味を不要なARIAで再実装しません。ARIAは標準HTMLだけでは不足する意味を補うために使い、標準要素の意味と衝突させません。

## 決定的検証との分担

HTML構文、必須属性、参照整合等の決定的条件は検証できます。一方、検証器が成功したことだけでは、プロダクトが表したい内容・関係・操作を適切なHTML意味構造で表現できているとは判断しません。そこはこの監査で確認します。

## 指摘

```text
監査観点:
現在のHTML:
表したい内容・関係・操作:
問題:
修正方針:
```

要素名そのものではなく、HTML上で失われている内容・関係・操作を示します。
