# 要求

プロダクトが満たすべき挙動・状態・制約を管理します。目的と対象範囲は `定義.md`、現在の設計は `../設計/概要.md` に置きます。

## 書く基準

- 利用者や外部システムから見て成立する必要があることを書く
- 主体、対象、状態、時点、入出力等、意味を決める条件を必要な範囲で明示する
- 実装方法を変えても残る意味を書く
- 外部API、法令、既存データ形式等が直接制約する場合は、その制約を残す
- 確認方法が分かりにくい重要要求は、テスト・検証器・契約等へ辿れるようにする

単純な要求へ連番を強制しません。複数箇所から参照する要求や、高リスク・高変更コストの要求には安定したIDを付けます。
