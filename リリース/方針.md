# リリース方針

通常開発から `main` へのマージ検証、その後のプロダクト固有リリース・デプロイまでの状態境界を管理します。検証の意味は `../開発/検証.md`、GitHub操作は `../skills/release/SKILL.md` が管理します。

## 通常開発とリリース検証を分ける

通常開発中は `release` ラベルを付けません。`release` ラベルありは、現在のPR先端を `main` マージ検証へ掛ける状態を表します。

## 成功結果は基底と先端の組に対して有効

成功した検証は、その実行が確認した基底SHAと先端SHAの組に対してだけ有効です。どちらかが変わった場合は再検証します。

## Draft / Readyをリリース状態にしない

`Draft` / `Ready` はGitHub上のレビュー状態です。リリース検証の状態とは分けます。

## マージと本番リリースを分ける

標準マージ方式はsquash mergeです。`main` へ入ったことと、本番デプロイ・パッケージ公開等が成功したことを別状態として扱います。

## 遠隔資源を有限資源として扱う

GitHub Actions、Cloudflare等のビルド・デプロイ割当量、費用、待ち時間を無視しません。公開価値のない小変更だけで本番ビルドを繰り返さず、まとめられる場合は意味のあるリリース単位へまとめます。

緊急修正、安全・セキュリティ、期限付き外部契約等で早期反映が必要な場合は遅らせません。

## 状態を区別する

CI未起動、待機中、実行中、リポジトリ側検査失敗、基盤停止、成功、`main` マージ済み、本番確認済みを区別します。
