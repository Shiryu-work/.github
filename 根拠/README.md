# 根拠

リポジトリが永続的に管理する構造化根拠の入口です。採用・確認・取得時点資料の判断は `方針.md` に従います。

## ここへ置くもの

反復して参照する資料の識別情報、発行主体、URL、確認日、支える主張・要求との関係、適用範囲、取得時点資料への参照等を置きます。

資料、リポジトリ内の主張、両者の支持関係は分けます。資料が登録されていることだけで、その資料がすべての主張を支えるとは扱いません。

同じ責務の新しいフィールドを作る場合は、可能な範囲で次へ揃えます。

```text
id            記録自身の安定ID
*_ref         別記録の安定ID参照
*_on          YYYY-MM-DDの日付
*_at          RFC 3339の時刻
*_url         URL
sha256        取得時点資料のSHA-256
```

既存のドメインモデルに独立した意味がある場合は、この形式へ無理に潰しません。

## 混ぜないもの

- プロダクトの目的・要求 → `../プロダクト/`
- 構成 → `../設計/`
- 根拠の採用基準 → `方針.md`
- 現在の作業・未処理一覧 → GitHub Issue
- 取得した資料本体の保存処理 → `保存連携.md`
- 一回限りの調査中メモ → 対話・Issue / PR等の作業文脈

同じ責務を `references/`、`evidence/`、`sources/` 等へ並行して作りません。
