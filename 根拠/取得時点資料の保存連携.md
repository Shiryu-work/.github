# 取得時点資料の保存連携

ChatGPTで外部情報を調査しながら開発するとき、重要な取得時点資料を `Shiryu-go/evidence-capture` へ保存依頼するための利用側の扱いを定めます。

根拠として採用するか、取得時点資料を保存する価値があるかは `方針.md` で判断します。資料情報や主張との関係はこのリポジトリの `README.md` に従って管理します。実際の取得、保存、完全性確認、保存先管理は `Shiryu-go/evidence-capture` が管理し、このリポジトリへ複製しません。

## 保存依頼

保存すると決めた資料は、利用側で資料を識別できる情報と、保存側が取得対象を特定するために必要な情報を明示して、`evidence-capture` の現在の連携仕様へ渡します。

少なくとも次へ戻れる状態を保ちます。

- 利用側で資料を識別するID
- 採用した資料URL
- 必要な場合の保存先識別情報
- 保存対象の種類・取得方法を決めるために必要な情報

具体的なフィールド名、Queue / Sheetへの投入方法、`status` の遷移、列仕様は `evidence-capture` が管理します。利用側で同じ手順や状態管理を作りません。

## 保存対象を取り違えない

案内ページが原資料へのリンクだけを持つ場合は、保存したい原資料を特定します。PDF、HTML、ZIP、CSV等を推測で同じものとして扱いません。

HTMLについても、取得したHTML、ブラウザ実行後DOM、スクリーンショット、描画済みPDFを同一視しません。何を保存したかの定義は `evidence-capture` の現在の連携仕様に従います。

## 保存成功

利用側は、`evidence-capture` が保存成功と完全性確認を確定した結果だけを保存済みとして扱います。現在の外部仕様では次を満たす結果です。

```text
status=SAVED
integrity=verified
```

未処理・失敗した保存依頼へ、Drive URL、SHA-256、保存状態等をAIが推測で補完しません。

## 利用側へ戻す情報

保存成功後は、後から「その時点で何を根拠にしたか」を追うために必要な参照だけを、このリポジトリの根拠記録へ戻します。

保存処理の運用履歴やQueueの内部状態を根拠管理へ複製しません。取得時点資料が保存されたこと自体は、その資料の権威や特定主張への支持を強くしません。
